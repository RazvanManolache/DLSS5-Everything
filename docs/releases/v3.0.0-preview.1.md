# DLSS5 Everything 3.0.0-preview.1

**Games are the main course. The extras have developed ambitions.**

## Download

- **Windows x64 ZIP:** extract into a writable folder and run `Dlss5CompatApp.exe`.
  The .NET runtime is included. Windows 10 2004 or newer is required for
  Screen Studio and Camera; install the
  [Microsoft Visual C++ x64 runtime](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
  required by native helpers.
- **Source ZIP:** application, native helper sources, tests and documentation.
  Initialize the DOSBox Enhanced submodule separately when developing that route.
- **SHA256SUMS.txt:** hashes of the release downloads.

Use [Components](../../README.md#getting-started) to obtain compatible Phoenix
and ReShade packages. Configure a compatible model separately, or explicitly
opt into the shared native-model downloads. **No NVIDIA DLL or model weights are
included in this release.** Optional vendor upscalers and runtimes retain their
own requirements and licenses.

The Android companion is maintained separately. Its source and APK are not
included in this repository or any attached release asset. The Windows Streamer
and documented LAN protocol remain available for separately supplied clients.

## Games first

- My Games and Discover are separate: keep your installed library tidy while
  scanning stores, folders and executables for more questionable commitments.
- Separate **Install** and **Verify & fix** actions. Uncertain renderer choices
  ask for a route; verification checks actual bridge output and offers a repair
  route instead of treating copied files as proof of rendering.
- Per-game controls, comparisons, saved settings and verification history.
- x86/x64 installation, compatibility transports and legacy translation routes,
  with backups, recovery and tracked removal.
- Original/Lightweight defaults, optional shared native model downloads and
  matching internal runtime-package deployment. Optional dependencies are checked
  before an explicitly selected mechanism replaces an installation.
- Clearer live-control availability, improved layout/accessibility and installer
  recovery handling. Hardware and route limitations remain visible.

## And then the side dishes escaped

- **Screen Studio:** window/display processing, live tuning, comparison,
  screenshots, Spout output and existing image/video file conversion.
- **Camera: make yourself more real.** Device-native Automatic mode, explicit
  mode discovery, Start/Stop, live strengths, preview, Spout and optional OBS
  Virtual Camera output for calling apps. Microphone capture and recording are
  not features of this release.
- **Android / Streamer:** paired TLS transport, raw/Pyrowave frames, app/follow
  capture, overlay and live controls. Phone pixels borrow the PC's GPU.
- Refreshed README with a preview game library and fictional desktop, Android
  and webcam demos. The processed images are actual Phoenix output; they do not
  claim live-stream performance or universal visual improvement.

## Acceptance boundaries

- The optimized native RTX route is the primary path. Native inference was
  exercised on an RTX 5080; do not infer coverage of every RTX generation.
- Portable backend speed and functionality depend on providers and hardware.
  AMD/Intel hardware and multi-GPU configurations are not broadly qualified here.
- Camera/device compatibility, sustained Wi-Fi behavior and Android OEM capture
  restrictions need wider testing. This release build did not touch a physical phone.
- VR remains experimental. A bridge or unit-test pass is not headset gameplay,
  eye correctness, latency or comfort qualification.
- Color-only desktop/camera inputs do not carry a game's full motion, depth or
  material guides. Enhancement is not automatically temporal Super Resolution.
- The Windows regression suite, native contracts and Android host unit tests are
  run separately from opt-in GPU/device tests. Check the attached validation
  receipt for this release's exact results and scope.

This is a **preview**, not a compatibility certificate for every game or device.
Reports with reproducible steps are welcome; perfectly ordinary bugs are welcome
too, although they could have knocked first.
